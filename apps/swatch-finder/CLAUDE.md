# apps/swatch-finder

Look up an Ohuhu Honolulu marker by code/name; shows its colour and location on the source swatch-sheet photo. See root `CLAUDE.md` for repo-wide conventions.

A static lookup over 320 Ohuhu Honolulu/Honolulu B marker swatches transcribed from 4 photographed reference sheets (the user's own physical charts, not a scraped source). Multi-file by design (the token-efficiency exception to the one-`index.html` default, see root `CLAUDE.md`'s Files section): `data.json` (320 objects: `code`/`name`/`oldCode`/`img`/`boxPct`/`hex`, no thumbnails) is `fetch()`ed at load (`searchInput` stays `disabled` with a `loadNote` message until it resolves), and `sw1.jpg`-`sw4.jpg` (the 4 full sheet photos, referenced as plain `<img src>`) sit alongside `index.html` — generated once by an offline Python pipeline (Pillow, not shipped in the app), not derived at runtime.

`boxPct` (`[x,y,w,h]` as % of the sheet image) came from manually calibrating each sheet's grid (row/column pixel bands, read off ruler-gridline overlays laid over crops of each photo — automated saturation/edge detection was tried first and abandoned: the hand-painted swatches bleed past their borders enough to defeat column/row projection) rather than a generic per-swatch algorithm; `hex` is an average of a padded-inward sample region (avoiding the painted border) rather than the manufacturer's actual ink colour. `SHEET_SIZE` (keyed `sw1`-`sw4`) holds each sheet photo's own natural pixel dimensions — the 4 sheets aren't identical size/aspect ratio, since each was cropped tight to its own physical card — and `cropFrameHTML(r, frameW, frameH)` uses it to convert a record's `boxPct` into a live "cover"-style crop (an oversized `<img>` absolutely positioned inside a fixed-pixel-size `overflow:hidden` frame) for grid-card and detail-header thumbnails, rather than shipping pre-cropped thumbnail images; the frame's CSS size must stay a fixed pixel value (not responsive) since the crop math is real-pixel arithmetic.

`search()` scores matches (exact code > exact old-code > code-prefix > old-code-prefix > exact name > name-prefix > name-substring > loose code-substring) via `norm()` (uppercase, whitespace-stripped) for codes and plain lowercase substring for names; a single confident code/old-code hit auto-opens the detail view instead of requiring an extra tap. The detail view's `.highlight-box` is one absolutely-positioned div at `boxPct` over the full sheet `<img>`, so it stays correctly placed at any render width.
